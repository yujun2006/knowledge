IMIX 密码轮转与 Session 热刷新架构设计文档
================================================

1. 概述
------------------------------------------------
本设计旨在为 IMIX 系统实现一套安全、自动化且低耦合的密码轮转（Password Rotation）机制。核心目标是解决硬编码密码的安全隐患，实现密码的周期性自动更新，并在更新后无缝刷新底层 IMIX 会话（Session），整个过程对周五下班后的业务无感知。

2. 核心架构设计
------------------------------------------------
系统采用控制平面（Cron Job）与数据平面（主进程）分离的架构。两者通过本地状态文件和轻量级通知机制进行解耦通信。

2.1 控制平面（Cron Job）
  - 职责：负责密码过期检查、新密码生成、目标系统轮转、本地状态落盘及触发刷新通知。
  - 触发时机：每周五下班后定时触发。
  - 核心特性：独立短生命周期进程，无状态，不持有业务 Session。

2.2 数据平面（主进程）
  - 职责：监听刷新通知，管理 IMIX Session 生命周期，实现凭证的热加载。
  - 核心特性：长驻服务，通过全局开关（isRefreshing）控制业务线程的流量放行。

3. 核心流程设计
------------------------------------------------

3.1 密码轮转控制流（Cron Job）
  1) 状态检查：读取本地 rotate-state.json，判断当前时间是否大于等于 expire_time。若未过期，直接执行业务并退出。
  2) 冷启动/首次轮转：若状态文件不存在，读取 Hardcode 旧密码，立即触发首次强制轮转。
  3) 生成新密码：根据密码规则生成新密码。若生成失败，直接报错退出。
  4) IMIX 黑盒子轮转：
       - 基于 IMIX 客户端 SDK，构造密码更新报文（如 PwdUpdReq）。
       - 采用异步转同步模式等待执行报告（ExecutionReport）。
       - 重试机制：若轮转失败，采用递增等待（Exponential Backoff）策略，最多重试 5 次（10s, 20s, 40s, 80s, 160s）。
  5) 状态落盘：轮转成功后，将新密码和新的过期时间（当前时间 + 7天）写入 rotate-state.json。
  6) 发送通知：向主进程发送 PostCall（如本地 HTTP 请求或信号文件），通知"密码已更新"。
  7) 进程退出：Cron Job 自身优雅退出。

3.2 Session 热刷新流（主进程）
  1) 接收通知：收到 PostCall 后，立即将内存中的 isRefreshing 标志位置为 true。
  2) 流量拦截：在 isRefreshing = true 期间，业务线程尝试发送消息时直接丢弃或返回"系统刷新中"（利用周五下班后无真实业务流量的窗口期，采用简单粗暴的拦截策略）。
  3) 优雅断开：遍历所有活跃的 IMIX Session，逐个发送 Logout 报文并关闭 TCP 连接，从 Session 列表中移除。
  4) 重新加载：重新读取 rotate-state.json，获取最新密码。
  5) 重新连接：使用新密码，逐个（或分批）重新发起 Logon，建立新的 Session 列表。
  6) 恢复服务：将 isRefreshing 标志位置为 false，恢复业务线程的消息收发。

4. 关键数据结构设计
------------------------------------------------

4.1 本地状态文件 (rotate-state.json)
{
  "current_password": "XyZ_9876543210",
  "expire_time": "2026-11-26T18:00:00",
  "last_rotate_time": "2026-11-19T18:00:00",
  "version": 1
}
  - current_password：当前生效的密码（建议配合文件权限控制，或后续升级为 AES 加密存储）。
  - expire_time：ISO 8601 格式的过期时间，便于人工排查。
  - last_rotate_time：上次成功轮转的时间，用于审计。
  - version：预留的扩展字段。

5. 安全与容错设计
------------------------------------------------
  1) 先外部后本地原则：必须先调用 IMIX 黑盒子更新目标系统成功，再写入本地状态文件。防止本地状态与目标系统不一致导致业务瘫痪。
  2) 幂等性保障：IMIX 轮转接口需保证幂等，避免 5 次重试导致目标系统产生冗余流水。
  3) 防自杀机制：Cron Job 仅负责发通知，不参与主进程的 Session 管理，彻底避免在 Stop Session 时误杀自身。
  4) 冷启动安全：首次运行强制轮转，消除旧密码的安全隐患，使系统从第一天起即纳入自动化生命周期。

6. 后续扩展建议
------------------------------------------------
  1) 告警集成：当 5 次重试均失败，或主进程重连 Session 失败时，需接入企业微信/钉钉/邮件告警，确保周一早上第一时间有人介入。
  2) 密码加密：当前状态文件为明文，后续可引入本地 KMS 或对称加密算法对 current_password 进行加密存储。
  3) 监控埋点：记录每次轮转的耗时、重试次数、Session 重连成功率等指标，接入 Prometheus/Grafana 监控体系。
